DX / Documentation

Langfuse Docs: Friction Notes from a First Run

I kept a friction log while building against the Python SDK rather than trying to reconstruct the experience afterwards.

The interesting problems weren't missing APIs. They were mismatches between what the system was doing and what a new user could infer from the symptom in front of them.

A script exits successfully but no trace appears, auto-instrumentation changes how you link a prompt to a generation, and legacy configuration names create ambiguity that the compatibility code hides instead of resolving.

Each note ends with the smallest docs change I'd actually propose in a PR.

About

I ended up in product marketing from the wrong direction.

I started close to developers: taking teams from an idea to a working integration, fixing onboarding gaps, owning docs, teaching SDKs, and watching launches fail in ways the launch metrics didn't explain.

The recurring problem was that technically correct products could still be badly understood. A feature could ship, the docs could exist, traffic could arrive — and adoption could stay near zero because the story explained the mechanism instead of the job.

That's the part I like working on.

My background is developer ecosystems and GTM professionally, mathematics and computer science academically, and enough Python and Rust to inspect what I'm supposed to be marketing before I form an opinion about it.

Berlin / remote. Currently interested in AI infrastructure and developer products where the technical details actually change the GTM story.
